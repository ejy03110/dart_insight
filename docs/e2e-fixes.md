## Q-07 진단과 보존

이전 구현은 모든 ZIP/XML 오류를 같은 메시지로 바꿔 실제 원인을 구분할 수 없었다.
UTF-16 BOM·CP949 확장 문자·허용 문자 엔티티/일반 앰퍼샌드가 기존 코드의 실패 조건임을
합성 회귀 입력으로 재현했지만 **그것이 2025-03-11 삼성전자 사업보고서 오류의 원인이라는 증거는 없다**.
실제 ZIP을 확보하기 전에는 원인을 확정하거나 실제 사업보고서 통과를 주장하지 않는다.

100 MiB 다운로드/XML 압축 해제 합계, XML 1,000개 제한을 유지한다. 헤더 크기뿐 아니라
읽은 바이트 수도 검사하며 경로를 디스크로 압축 해제하지 않는다. 원격 DTD를 가져오거나
엔티티 선언을 확장하지 않는다. 알려지지 않은 엔티티/손상된 XML은 본문을 임의로 복구하지 않고
XML 순번·행·열을 제공하며 실패한다. 대용량 테스트는 5만 행/2 MiB 이상의 표와 다중 XML이며
실제 사업보고서 파일 전체에 대한 성능 증거는 아니다.

실제 원문 수집에서 파싱이 실패하면 제한 이내의 원본 ZIP만 다음 위치에 **새 파일**로 보존한다.

`DART_DATA_DIR/diagnostics/document-접수번호-고유값.zip`

인증키가 든 요청 URL·HTTP 오류 응답·본문 내용은 오류 메시지에 출력하지 않는다.
진단 ZIP은 `.local/data` 기본 경로 사용 시 Git 제외 대상이며 제출물/Git에 추가하지 않는다.
기존 `.env`·SQLite·문서·Chroma·모델 캐시를 지우거나 초기화하지 않는다.

## Windows 로컬 재검증

실행 중인 Streamlit을 종료하고 기존 작업 트리가 깨끗한지 먼저 확인한다.
로컬 수정이 있으면 보존한 후 브랜치를 갱신한다. 기존 `.venv`와 DB를 그대로 사용한다.

```powershell
git status --short
git switch feat/required-rag-integration
git pull --ff-only origin feat/required-rag-integration
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m streamlit run app.py
```

1. 메타데이터 1,065건과 기존 CHROMA_DB_DIR을 확인한다. 재수집/전체 재색인/DB 삭제는 필요 없다.
2. 삼성전자 `사업보고서 (2024.12)`, 제출일 `2025-03-11`을 선택하고 **공시 핵심 분석 실행**.
3. 성공하면 요약/명시된 위험/추가 확인/출처를 검수한다. 실패하면 구체 오류와 새 진단 ZIP을 확인한다.
   실제 ZIP을 다음 명령으로 검사할 수 있다. API 키·모델·네트워크 없이 실행된다.

```powershell
# 기본 데이터 경로일 때. 사용자 지정 DART_DATA_DIR이면 경로를 그 값으로 바꿉니다.
$zip = Get-ChildItem .local\data\diagnostics\document-*.zip | Sort-Object LastWriteTime -Descending | Select-Object -First 1
.\.venv\Scripts\python.exe -m dart_insight.inspect_document --input $zip.FullName
```

진단 결과에는 XML 순번·크기·선택 인코딩·변환 건수·오류 행/열을 표시하며 원문 본문은 출력하지 않는다.
사용자 파일 전체의 경로나 ZIP 멤버 이름·오류 원문도 출력하지 않는다.

4. 분석 후 추가 질문을 입력한다. 분석 결과가 그대로 유지되고 추가 질문만 말풍선에 생기는지 확인한다.
   다른 공시로 이동한 뒤 복귀해 분석과 채팅이 각각 복원되는지도 확인한다.
5. `2025년 삼성전자의 사업보고서`, `삼성전자 2024 사업연도 사업보고서`,
   `삼성전자 2035년 사업보고서`를 비교한다. 각각 제출연도/사업연도 기준과 실제 결과를 확인한다.
6. 임원 소유상황보고서에 취득 수량·원인을 질문한다. 장내매수는 방식으로 표시하며
   목적 근거가 없으면 확인되지 않는다고 말하는지 실제 문서와 대조한다.
7. 같은 URL의 근거 2/3이 링크 하나에 묶이고 각 청크를 펼쳐 확인할 수 있는지 점검한다.
8. 단일 공시 질문과 기간별 비교 질문의 검색어·후보/선별 목록을 비교한다.
   비교 질문에 실제 관련 후보가 있는데도 제외되면 해당 후보/선별 결과를 근거로 후속 수정한다.
9. OpenDART 날짜 입력을 바꾸고 안내 명령도 즉시 같은 기간인지 확인한다.

## 검증 한계

이번 머신에는 실제 1,065건 DB·문제 ZIP·DART/GMS 키가 없다. OpenDART 루트 연결 점검은
HTTP 503 응답이었으며 인증된 document.xml/GMS 요청을 실행하지 않았다.
자동화 테스트는 합성 ZIP/문서와 Mock API/임베딩, 실제 임시 Chroma/SQLite/LangGraph/AppTest를 사용한다.
사용자가 보고한 Windows 실행·공시 분석/채팅·출처/기록 복원 성공은 사용자 실검증이며
이번 머신의 BGE 검색 품질/GMS 인증 검증으로 바꾸어 기록하지 않는다.
