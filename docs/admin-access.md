# 관리자 진단 접근

일반 화면에는 진단 메뉴가 나타나지 않는다. 관리자 설정이 없거나 잘못되면 접근을 차단한다.
기존 DART/GMS 키와 독립된 설정이며, 서비스 설정·비밀번호를 소스나 Git에 넣지 않는다.

## 설정과 로그인

1. 저장소 루트에서 비밀번호 해시를 생성한다.

   ```bash
   .venv/bin/python -m dart_insight.ui.admin_auth
   ```

   16자 이상의 긴 비밀번호를 두 번 입력한다. 입력은 화면에 표시하지 않는다.
   출력되는 `pbkdf2_sha256$...` 문자열은 비밀번호 해시다. 이것도 안전하게 보관하고 Git에 넣지 않는다.

2. 서버 환경변수 `DART_ADMIN_PASSWORD_HASH`에 생성된 전체 문자열을 설정하거나,
   Git에서 제외된 `.streamlit/secrets.toml` 또는 배포 플랫폼 Streamlit secrets의 같은 이름에 저장한다.
   `$`가 포함되므로 셸에서 설정할 때 작은따옴표로 감싸고, 명령 기록에 남지 않는 플랫폼 비밀 설정을 권장한다.
   실제 값은 문서·채팅·커밋에 붙이지 않는다. 환경변수가 secrets보다 우선한다.
   일반 `.env`에 쓰는 것만으로는 관리자 인증에 반영되지 않는다. 프로세스 환경변수나 Streamlit secrets를 사용한다.

3. Streamlit 서버를 재시작한다.

   ```bash
   .venv/bin/python -m streamlit run app.py
   ```

4. 서비스 주소에 `?admin=login`을 붙여 로그인 화면을 연다. 기존 쿼리가 있으면 `&admin=login`을 사용한다.
   이 주소 자체는 비밀이나 인증 수단이 아니다. 생성할 때 사용한 비밀번호로 로그인한다.
   성공하면 사이드바에 **진단 도구**와 **관리자 로그아웃**이 나타난다.
   진단 화면에서도 OpenDART 연결은 버튼을 눌러야 실행된다.

5. 종료할 때 **관리자 로그아웃**을 누른다. 분석·대화 데이터는 지우지 않으며 진단 권한만 회수한다.

## 검증 범위와 제한

- PBKDF2-HMAC-SHA256 600,000회, 랜덤 salt, 상수 시간 비교로 비밀번호를 검증한다.
  256비트 랜덤 proof는 서버 메모리의 grant와 서버가 부여한 Streamlit session ID에 결합한다.
  세션 상태의 `is_admin`, `diagnostic_open` 같은 플래그나 임의 proof만으로 인증되지 않는다.
- `render_diagnostics()`가 데이터 저장소나 API에 접근하기 전에 서버 권한을 재검사한다.
  URL·쿼리·UI 가드만으로 보호하지 않는다. Streamlit 실행 문맥이 없는 직접 호출도 거절한다.
- 권한 유효기간은 로그인 후 30분이며 자동 연장하지 않는다. 로그아웃·프로세스 재시작·설정 해시 변경 시
  재로그인이 필요하다. 다른 접속으로 proof를 복사해도 사용할 수 없다.
- 프로세스 전체에서 최근 60초 동안 실패 5회면 해당 구간의 추가 로그인을 차단한다.
  새 접속으로 바꿔도 동일 프로세스의 제한은 유지된다. 공격자가 관리자 로그인을 일시 방해할 수 있다.
- 단일 Streamlit 프로세스용 공유 관리자 비밀번호 방식이다. 사용자별 계정·MFA·분산 세션/제한 저장소·
  조직 SSO는 구현하지 않았다. 여러 워커에서는 세션 고정이나 외부 인증 체계를 별도로 설계해야 한다.
- 외부 공개 시 HTTPS와 배포 플랫폼의 접근 제어·요청 제한을 사용한다. Streamlit 기본 XSRF/CORS 보호를 끄지 않는다.
  이 보호는 애플리케이션의 진단 진입점을 대상으로 하며 서버에서 임의 Python 코드를 실행할 수 있는 공격자를 격리하지 않는다.
- 로그인 입력은 처리 후 비우고, 비밀번호 원문·해시·proof를 로그나 진단 출력에 표시하지 않는다.
  서버 메모리 grant나 비밀 설정을 외부에 공개하지 않는다.

## 분석 화면

일반 분석은 기술 단계/모델 정보를 출력하지 않고 기본 스피너로 대기한다. 백엔드 로깅은 유지하며
UI 오류 추적에는 정해진 단계 분류와 예외 종류만 추가한다. 오류 원문을 화면에 출력하지 않는다.
채팅은 고정 높이 스크롤 없이 전체 답변을 대화 순서대로 표시한다. 원문 답변·근거·경고는 유지한다.
