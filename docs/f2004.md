# F2004 첫 단계: 문서 모델과 수집 상태 원장

이 단계는 외부 요청·후보 선별·파싱·실제 색인을 구현하지 않는다.
F2001~F2003과 Chroma 코드는 변경하지 않는다.

## 모델

`dart_insight.data.documents.DocumentCandidate`는 다음을 보존한다.

- `item_rcept_no`: 사용자가 선택한 공시 접수번호
- `document_rcept_no`: 실제 원문 공시 접수번호(선택 공시와 다를 수 있음)
- `title`, `corp_code`, `source_url`, `source_type`

`CollectedDocument`는 위 필드에 `text`, 시간대가 있는 ISO `collected_at`을 추가한다.
두 모델은 불변 dataclass이며 `to_dict()`로 직렬화할 수 있다.
접수번호·기업코드·제목·본문·수집 시각을 검증하고, 출처는 키 없는 공식 DART 뷰어 URL만 받는다.
인증키가 들어간 다운로드 URL을 저장하지 않는다. 현재 출처 유형은 `opendart_document`만 지원한다.
원문 접수번호별 본문 한 개를 표현하며, ZIP 내부 파일·청크 식별자는 후속 단계의 범위다.

## CollectionLedger

`dart_insight.data.collection_ledger.CollectionLedger(path)`는 지정한 SQLite 파일을 생성/재사용한다.
권장 경로는 `load_settings().data_dir / "collection.sqlite3"`이며 Git에 포함하지 않는다.
키는 `(item_rcept_no, normalize_query(query), source)`다.
정규화는 Unicode NFKC → 연속 공백 축약 → casefold이며, 동의어·의미적 유사성은 합치지 않는다.

| 상태 | 의미 | 후속 호출자가 해야 할 일 |
|---|---|---|
| 없음 | 아직 등록하지 않음 | `ensure_pending()` |
| `pending` | 수집 미완료, 실패했어도 재시도 가능 | 수집을 다시 수행 |
| `collected` | 전체 수집 문서와 출처 저장 완료, 색인 미완료 | 저장 문서로 F2005 색인 수행/재시도 |
| `indexed` | 호출자가 색인 성공을 확인하고 기록 | 완료 작업 생략 |

```python
from dart_insight.config import load_settings
from dart_insight.data.collection_ledger import CollectionLedger

ledger = CollectionLedger(load_settings().data_dir / "collection.sqlite3")
ledger.ensure_pending(selected.rcept_no, query)
record = ledger.get(selected.rcept_no, query)
# 후속 collector가 모든 원문 수집에 성공했을 때만:
# ledger.mark_collected(selected.rcept_no, query, collected_documents)
# 후속 F2005가 실제 색인·검증에 성공했을 때만:
# ledger.mark_indexed(selected.rcept_no, query)
```

`get()`은 없으면 None, 있으면 상태·정규화 검색어·출처·수집 문서·갱신 시각을 반환한다.
수집 실패/부분 성공이면 `mark_collected()`를 호출하지 않고 pending을 유지한다.
빈 문서 목록으로 완료 처리할 수 없으며, 전체 수집 성공 여부는 후속 collector가 판정해야 한다.
색인 실패이면 `mark_indexed()`를 호출하지 않고 collected를 유지한다.
pending에서 indexed로 바로 전환하거나 완료 문서를 다른 내용으로 덮어쓸 수 없다.
동일 완료 배치 재전달과 중복 등록은 안전하며 indexed 상태를 낮추지 않는다.
문서와 상태는 같은 트랜잭션으로 저장되고 저장 실패는 롤백된다.

이 원장은 작업 완료 상태를 기록할 뿐 외부 작업을 실행하지 않으며 동시 수집자의 작업 점유 잠금은 아니다.
F2004의 선택 공시 강제 수집, API 호출 생략 분기, F2005 완료 후 상태 갱신은 후속 서비스에서 연결해야 한다.

## F2004-2: 로컬 메타데이터 후보 검색

`dart_insight.services.candidate_search.search_candidates()`는 기존 `dart_metadata`와
`query_metadata()`를 사용한다. 외부 후보 검색 API는 아니며, 현재 색인 범위에서만 찾는다.
기존 DocumentCandidate·Disclosure·Chroma 스키마·CollectionLedger는 변경하지 않는다.

```python
from dart_insight.services.candidate_search import search_candidates
from dart_insight.vectorstore.embeddings import create_embeddings
from dart_insight.vectorstore.metadata import open_metadata_collection

# settings는 load_settings(), selected는 사용자가 선택한 기존 Disclosure,
# queries는 F2003 결과의 ["queries"], db_dir은 실제 기존 DB 경로다.
collection = open_metadata_collection(db_dir, settings.embedding_model, create=False)
result = search_candidates(
    collection, queries, selected, create_embeddings(settings),
    model=settings.embedding_model, top_k=settings.top_k,
)
for hit in result.candidates:
    print(hit.candidate.to_dict(), hit.corp_name, hit.best_similarity)
    for match in hit.matches:
        print(match.query, match.distance, match.similarity)
```

- 입력 검색어는 양끝 공백·동일 문자열 중복만 제거하고 각각 검색한다. 빈 리스트는 허용하되 빈 문자열은 오류다.
- `top_k`는 **검색어별** 1~100이다. 최종 후보 수 제한이 아니며 여러 결과의 합집합을 반환한다.
- 선택적 `corp_code` 필터를 전달할 수 있다. 생략하면 기업을 제한하지 않는다.
- 접수번호로 중복 제거하고 모든 검색어·거리 근거를 유지한다. 선택 공시는 필터·순위와 관계없이 포함한다.
- 기존 DocumentCandidate에는 새 필드를 추가하지 않는다. `CandidateHit.candidate`에 기존 모델을 담고
  회사명·검색 근거·선택 여부는 wrapper에 저장한다. 회사명·제목·URL은 입력/메타데이터에서 읽으며 누락을 추측하지 않는다.
- 거리 원본을 보존하며 cosine 유사도는 `1 - distance`다. 확률이나 보정된 관련성 점수가 아니다.
- 점수가 있는 후보는 최소 거리 순으로 정렬하고 동점이면 접수번호 순이다. 선택 공시는 항상 첫 번째다.
- 강제 포함만 된 선택 공시는 `matches=()`, 점수 None이다. 가짜 거리·검색어를 만들지 않는다.
- `result.status`는 검색으로 얻은 고유 공시가 있으면 `ok`, 없으면 `empty`다.
  `matched_count`는 검색으로 얻은 고유 접수번호 수이며 강제 포함만 된 공시는 세지 않는다.
  `empty`여도 선택 공시는 반환된다. `empty_queries`에는 결과가 없던 검색어를 기록한다.
- 검색 중 하나라도 실패하면 `CandidateSearchError`로 종료하며 부분/빈 성공으로 대체하지 않는다.
  잘못된 ID·필수 메타데이터·점수·동일 접수번호의 상충 정보도 실패다.
- 기존 모델·벡터 프로필·차원 검증을 재사용하며 cosine `dart_metadata`만 허용한다.
- 원장 갱신·LLM 선별·다운로드·색인은 수행하지 않는다. 로컬 BGE 모델은 실제 검색 시 필요하다.

검증: 신규 10개 포함 전체 90개 통과(실패/skip 0). 임시 Chroma에는 테스트 fixture만 색인하고,
검색 전후 문서·메타데이터가 그대로인지 확인한다. 실제 사용자 1,065건 DB·실제 BGE 검색 품질은 미검증이다.
