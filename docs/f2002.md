# F2002 메타데이터 임베딩·색인

기준: 원본 PDF p.11~12. 공시당 텍스트 1개를 임베딩하고 저장 건수를 확인하며,
같은 자료를 다시 실행해도 중복 저장하지 않아야 한다.
F2001 코드는 변경하지 않았으며 원문·문서 컬렉션·RAG는 이번 범위가 아니다.

## 입력과 실제 데이터 확인 상태

F2001의 `schema_version=1`, `requirement=F2001`, `summary.status=complete` JSON을 받는다.
입력 경로는 반드시 `--input`으로 지정하며 특정 `run-*` 폴더나 최신 폴더 자동 탐색에 의존하지 않는다.
입력 파일의 전체 건수·100건 이상·접수번호 고유성·필수 필드·날짜·키 없는 원문 URL·색인 텍스트,
세 기업 코드 매핑과 기업별 집계를 검증한다. 실패하면 DB 생성·임베딩 전에 중단한다.

사용자 제공 F2001 검증 결과: **1,065건(삼성전자 827 / 현대자동차 172 / 금양 66), complete**.
이는 사용자 로컬 실행 결과이며, 해당 JSON은 Codex 파일시스템에 없어 이곳에서 직접 재검증하지 않았다.
이번에 실제 OpenAI 임베딩 API는 호출하지 않았다.

## dry-run (API 키 불필요)

```bash
cd /workspace/dart_insight
source .venv/bin/activate
python -m dart_insight.index_metadata \
  --input .local/data/metadata/run-7kvbb30c/collection.json \
  --dry-run
```

출력: `stage=validated_input`, `dry_run=true`, `document_count`, `unique_id_count`,
`embedding_model`, 기업별 `corp_code`·`corp_name`·건수.
실제 파일 경로로 바꿔 실행한다. 위 run 이름은 사용자가 제공한 **예시 입력 경로**다.
dry-run은 Chroma DB를 열거나 생성하지 않고, OpenAI 클라이언트·토큰화 모델도 생성하지 않는다.
색인 완료나 실제 임베딩 비용 측정 결과가 아니다. 정상 종료 0, 입력 검증/파일 오류 1이다.

## 실제 임베딩 실행 (사용자가 명시적으로 실행)

필수 환경변수: `OPENAI_API_KEY`. 환경변수 또는 저장소 `.env`에 안전하게 설정한다.
CLI는 Streamlit Secrets 파일을 직접 읽지 않는다. OpenDART 키는 이 단계에 필요하지 않다.
선택 설정: `OPENAI_EMBEDDING_MODEL`(기본 `text-embedding-3-small`),
`DART_DATA_DIR`(기본 `.local/data`), `DART_TIMEOUT_SECONDS`(기존 HTTP timeout 재사용).
설치 의존성은 기존 requirements를 그대로 사용한다. 실제 API에는 `api.openai.com` 접근이 필요하다.

```bash
python -m dart_insight.index_metadata \
  --input .local/data/metadata/run-7kvbb30c/collection.json \
  --db-dir .local/data/chroma \
  --batch-size 64
```

실제 API 호출 전 입력 문서 수와 모델을 stdout에 출력·flush한다.
그 후 검증된 데이터만 명시적 CLI에서 생성한 OpenAIEmbeddings에 전달한다.
모듈 import·앱 시작·dry-run·단위 테스트에서는 실제 임베딩을 수행하지 않는다.
토큰 길이 자동 분할은 사용하지 않으므로 비정상적으로 긴 입력은 API 제한 오류가 날 수 있다.
에러에는 키·provider 응답·traceback을 출력하지 않는다.

## 저장·필터·중복 방지

- 로컬 persistent Chroma의 **단일 `dart_metadata` 컬렉션**을 사용한다.
- ID: `meta:{rcept_no}`. 문서 본문은 F2001 `index_text` 그대로다.
- 메타데이터: `corp_code`, `corp_name`, `rcept_no`, `report_nm`, `rcept_dt`,
  `source_url`, `disclosure_type`, `source_type`, `content_hash`.
- 기업별 구분은 컬렉션 분리가 아닌 `collection.get(where={"corp_code": "기업코드"})` 필터로 한다.
  기업코드는 F2001 JSON의 공식 매핑을 사용하며 임의로 추측하지 않는다.
- Chroma 기본 임베딩 함수를 끄고 명시적으로 계산한 벡터만 upsert한다.
- ID·문서·메타데이터 해시가 같으면 임베딩과 upsert를 생략한다. 변경 시 같은 ID로 갱신한다.
- 모델명은 컬렉션에 기록한다. 같은 DB에 다른 모델을 지정하면 API 전에 중단한다.
  새 모델은 다른 `--db-dir`로 색인한다. 같은 이름의 모델 내부 버전 변경은 별도 관리가 필요하다.
- 입력에 없는 과거 자료는 삭제하지 않는다. 다른 데이터가 이미 있으면 컬렉션 전체 건수는 입력보다 클 수 있다.
- 임베딩 실패 시 이전 배치는 저장되어 있을 수 있다. 같은 입력·DB·모델로 재실행하면 저장된 배치는 건너뛴다.

색인 완료 출력: 입력/실제 임베딩/생략 건수, `verified_input_count`,
`before`·`after`의 전체 및 기업별 `by_corp_code` 건수, `count_delta`.
저장 후 입력의 모든 ID·텍스트·메타데이터를 다시 읽어 검증한다.
기업별 출력은 입력에 포함된 세 기업의 필터 결과다. 전체 건수에는 보존된 이전 자료도 포함된다.

## 재실행으로 중복 검증

위 실제 색인 명령을 **같은 입력·DB 경로·모델**로 두 번 실행한다.
비어 있던 DB에 사용자 제공 파일이 정상 색인된다면 예상 결과는 다음과 같다(실측 아님).

| 항목 | 첫 실행 예상 | 동일 재실행 예상 |
|---|---:|---:|
| 전체 저장 건수 | 1,065 | 1,065 |
| 삼성전자 / 현대자동차 / 금양 | 827 / 172 / 66 | 827 / 172 / 66 |
| embedded_count | 1,065 | 0 |
| skipped_count | 0 | 1,065 |
| count_delta | 1,065 | 0 |

두 실행의 stdout과 종료 코드를 보관한다. 이 실제 API 결과는 현재 미검증이다.
화면 상시 건수 표시는 원본의 예시이며 이번에는 CLI 건수 조회를 구현했다. Streamlit 화면은 연결 확인용 그대로다.

## 비용 영향 요소

과금은 문서 수 자체보다 **실제로 전송한 텍스트의 입력 토큰 수 × 선택 모델의 현재 단가**에 영향을 받는다.
한국어·공시명 길이·텍스트 구성에 따라 같은 1,065건도 토큰 수가 다르다.
dry-run의 문서 수는 정확하지만 토큰 사용량·금액 견적은 아니다. 정확한 단가는 실행 시 공식 요금표를 확인한다.
동일 자료 재실행은 호출을 생략하고, 새 문서·변경 텍스트/메타데이터는 재임베딩한다.
새 DB 경로는 모든 자료를 다시 임베딩한다. 응답 실패 후 재시도도 중복 과금 가능성에 영향을 줄 수 있다.
batch-size는 요청 수·처리 시간·실패 범위에 영향을 주지만 원문 총 토큰 수를 줄이지 않는다.
Chroma 저장은 로컬 디스크이며 별도 Chroma 호스팅을 사용하지 않는다.
