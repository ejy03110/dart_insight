# F2002 로컬 BGE-M3 임베딩·색인

기준: 원본 PDF p.11~12. 공시당 텍스트 하나를 임베딩하고 저장 수·재실행 중복 없음 확인.
SSAFY GMS `https://gms.ssafy.io/gmsapi/`에서 OpenAIEmbeddings가
`403 Target domain embeddings is not allowed`로 실패했다는 사용자 보고에 따라
임베딩을 **로컬 BAAI/bge-m3**로 전환했다. GMS는 향후 LLM용이며 이번에 LLM 연결을 구현하지 않았다.
F2001 코드·collection.json·수집 자료는 수정하지 않는다. 원문·RAG는 별도 후속 기능이다.

## 설치·설정

```bash
cd /workspace/dart_insight
source .venv/bin/activate
python -m pip install -r requirements.txt
```

추가 패키지: sentence-transformers 5.1.2, transformers 4.57.3, torch 2.9.0 CPU.
기존 PDF 지정 패키지 버전은 유지했다. CPU wheel은 공식 PyTorch 인덱스에서 TLS 검증으로 받는다.
requirements.lock.txt는 검증된 Linux/Python 3.12 CPU 환경이다. macOS에서는 플랫폼 조건이 있는
requirements.txt를 사용한다. GPU 사용은 해당 장치용 PyTorch 설치가 별도로 필요하며 이번 검증 범위 밖이다.

설정(환경변수 또는 .env, 값은 .env.example 참조):

| 설정 | 기본값·용도 |
|---|---|
| EMBEDDING_MODEL | BAAI/bge-m3. 현재 어댑터는 이 모델만 허용 |
| EMBEDDING_DEVICE | cpu |
| EMBEDDING_CACHE_DIR | 미설정 시 DART_DATA_DIR/models |
| DART_DATA_DIR | .local/data, 기존 설정 재사용 |

OPENAI_API_KEY·GMS 키는 임베딩·검색에 필요하지 않다. 기존 OPENAI_EMBEDDING_MODEL은 무시한다.
기존 .env가 있다면 파일을 덮어쓰지 말고 새 설정만 반영한다.
모델 로드와 문서·질의 임베딩은 사용자 머신에서 수행되며 원문 텍스트를 OpenAI/GMS에 보내지 않는다.
첫 실제 실행에는 Hugging Face의 모델 가중치(수 GB)·토크나이저 다운로드가 필요할 수 있다.
CPU 시간·RAM·디스크를 사용하므로 처음에는 batch-size 16을 권장하고 메모리가 부족하면 줄인다.
검증 과정에서는 패키지만 설치했으며 실제 BGE-M3 가중치 다운로드·실제 모델 추론은 수행하지 않았다.

## 입력·dry-run

F2001 schema_version=1, requirement=F2001, summary.status=complete JSON의 경로를 --input으로 받는다.
기존 사용자 데이터: 1,065건(삼성전자 827 / 현대자동차 172 / 금양 66), complete.
이 JSON은 사용자 로컬에 있으며 현재 Codex에서 직접 읽거나 변경하지 않았다.

```bash
python -m dart_insight.index_metadata \
  --input .local/data/metadata/run-7kvbb30c/collection.json --dry-run
```

실행별 폴더명은 예시다. 임의의 실제 파일 경로를 사용할 수 있다.
--input, --db-dir, --batch-size, --dry-run 옵션은 유지한다.
입력 건수·필수 필드·고유 ID·날짜·키 없는 원문 URL·텍스트·기업별 집계를 검증하고 모델·건수를 출력한다.
dry-run은 모델 어댑터 생성·sentence-transformers import·모델 다운로드·encode·DB 생성/열기를 하지 않는다.
정상 종료 0, 잘못된 입력/실행 오류는 1이다.

## 색인과 기존 벡터 호환성

```bash
# 기존 OpenAI DB를 보존하고 새 경로에 동일 collection.json 재색인
python -m dart_insight.index_metadata \
  --input .local/data/metadata/run-7kvbb30c/collection.json \
  --db-dir .local/data/chroma_bge_m3 --batch-size 16
```

--db-dir 생략 시 기존처럼 DART_DATA_DIR/chroma를 사용한다. 이전 모델의 DB가 있으면 중단한다.
기존 DB를 자동 삭제·덮어쓰기·메타데이터만 수정해서 재사용하지 않는다.
OpenAI 벡터와 BGE-M3 벡터는 차원이 같더라도 같은 공간이 아니므로 **같은 원본에서 다시 계산**해야 한다.
새 DB에서도 컬렉션 이름은 단일 dart_metadata이며 기업별 컬렉션을 만들지 않는다.

- ID는 meta:{rcept_no}, 본문은 F2001 index_text 그대로다.
- corp_code·corp_name·rcept_no·report_nm·rcept_dt·source_url·공시 유형·source_type·content_hash를 저장한다.
- BGE-M3 dense 벡터는 1024차원이며 문서와 질의 모두 정규화한다. sparse/multi-vector는 사용하지 않는다.
- 컬렉션 모델명·벡터 프로필(backend/차원/정규화)·기존 벡터 차원을 검사한다.
  모델/프로필이 다르거나 정보가 없으면 새 DB 경로로 재색인해야 한다.
- Chroma 기본 임베딩 함수는 비활성화한다. 지연 로딩 어댑터가 첫 실제 encode에서만 모델을 로드한다.
- 모델·ID·텍스트·메타데이터가 같으면 임베딩/upsert를 생략한다. 같은 명령 재실행으로 중복되지 않는다.
- 입력에 없는 기존 자료는 삭제하지 않는다. 부분 배치 실패는 같은 명령으로 재개한다.
- 모델명/프로필이 같아도 원격 가중치가 바뀔 가능성까지 자동 검출하지는 않는다.
  검증한 캐시를 보존하고 모델 가중치를 교체할 때도 새 DB를 사용한다.

색인 전 문서 수·모델을 출력·flush한다. 완료 후 before/after 전체·corp_code별 수,
embedded_count, skipped_count, count_delta, verified_input_count를 출력한다.
동일 명령을 두 번 실행하여 after.total이 유지되고 count_delta=0, embedded_count=0인지 확인한다.
처음 비어 있던 DB에 사용자 데이터가 모두 색인되면 1,065건·827/172/66을 기대하지만 현재 실측 결과는 아니다.

## 같은 모델로 검색

```bash
python -m dart_insight.search_metadata \
  --db-dir .local/data/chroma_bge_m3 \
  --query "삼성전자 사업보고서" --top-k 5

# 특정 기업만: 실제 corp_code는 입력 JSON의 공식 매핑에서 확인
python -m dart_insight.search_metadata \
  --db-dir .local/data/chroma_bge_m3 \
  --query "사업보고서" --corp-code 00126380 --top-k 5
```

색인과 검색은 vectorstore/embeddings.py의 같은 create_embeddings() 팩토리와
embed_documents()/embed_query() 인코더·정규화를 사용한다. 모델 불일치는 검색 전에도 차단한다.
기존 컬렉션만 열며 누락된 DB를 검색 과정에서 만들지 않는다. 기업 필터와 원문 URL이 있는 결과를 반환한다.
이는 메타데이터 단독 검색 기반으로, F2006의 두 컬렉션 병합·근거 구성이나 RAG 답변 완성이 아니다.

모델 캐시를 완전히 준비한 뒤 HF_HUB_OFFLINE=1 및 TRANSFORMERS_OFFLINE=1로 실행하면
다운로드를 차단할 수 있다. 캐시가 없으면 실패하며 다른 모델/가상 벡터로 대신하지 않는다.
캐시 위치·환경변수 설정 방법은 사용자 OS에 맞게 적용한다.

## 테스트·실제 검증 상태

```bash
python -m unittest discover -s tests -v
```

테스트는 Mock 인코더/벡터와 임시 Chroma만 사용하며 외부 API·가중치 다운로드를 수행하지 않는다.
온라인 다운로드 차단 환경변수에서도 전체 58개 테스트가 통과했다.
새 테스트는 지연 로딩·동일 질의/문서 인코더·정규화·1024차원·키 불필요·재색인 생략·필터 검색·
기존 OpenAI 데이터 보존·미확인 프로필/차원 차단·잘못된 모델 거절·검색 CLI를 검증한다.
실제 BGE-M3의 1,065건 임베딩 시간·메모리·저장 수·검색 품질은 미검증이며 로컬 실행으로 추가 확인해야 한다.
API 임베딩 과금은 없고 모델 다운로드 트래픽·저장 공간·로컬 연산 자원을 사용한다.
