# 필수 기능 통합: 공식 PDF 대조 및 실행 검증

기준: 사용자가 첨부한 `AI코어프로젝트_2회차_요구사항정의서.pdf` 23쪽 전체.
필수 조항 p.11~15, 비기능 p.10, 실행 검증 p.18~19, 제출물 p.21~23을 확인했다.
PDF 원본은 비공개 문서로 저장소에 추가하지 않는다. 개발 프롬프트는 도메인별 구현 선택이며 PDF와 충돌할 때 PDF가 우선한다.

## 우선순위와 범위 판단

- 기존 AGENTS의 단계별 구현 규칙보다 사용자의 이번 **필수 기능 통합 구현 요청**을 우선한다.
- Python은 PDF의 3.10+가 기준이다. 클라우드 3.12 / 사용자 Windows 3.11을 구분한다.
- F2004의 외부 출처 검색은 내부 Chroma 검색만으로 대체할 수 없다. OpenDART 목록 API의 전체 페이지 검색을 추가하고 기존 후보 검색은 보완 수단으로 재사용한다.
- F2004는 선택 항목 자체 문서를 선별·길이 규칙보다 우선하여 항상 색인하도록 요구한다. LLM이 빈 배열을 반환해도 선택 공시 원문을 강제 포함한다. 원문이 없거나 파싱이 실패하면 완료로 처리하지 않는다.
- 메타데이터/외부 문서 출처 유형 구분은 F2007의 필수 조건이다. 서로 다른 원문 출처를 결합하는 F2016과 구분한다. 온라인 OpenDART와 그 원문의 오프라인 묶음은 대체 모드다.
- F2010은 도메인 기능 1개 이상이다. 공시 요약·명시된 위험 요인·추가 확인 사항을 이번 기능으로 선택한다.
- F2011은 벡터 후보를 그대로 노출하면 안 된다. 별도의 조건 선별 프롬프트를 적용하고 허용된 후보 ID만 수용한다.
- F2013~F2016(별도 프론트엔드, MMR, RAG 전후 비교, 다종 원문 출처 결합)은 구현하지 않는다. PDF 4.6의 비교도 F2015 선택 시에만 해당한다.

## 구조와 데이터 보존

기존 F2004 브랜치 `02c947f` 및 Windows 후속 `adc7475` 계보를 통합 개발 브랜치로 merge했다.
이 계보에는 SQLite cursor/connection 명시 종료 수정도 포함된다. 대체 `sqlite closing` 브랜치의 중복 변경을 덮어 병합하지 않았다.
기존 F2001/F2002의 수집/메타데이터 색인 구현과 잠금 파일은 유지한다.

- `services/original_documents.py`: 외부 후보 검색/실제 ZIP/XML/BundleSource.
- `data/collection_ledger.py`: 기존 collection_queries 스키마 유지, additive 테이블 추가.
  `collection_plans`는 후보/선별 계획, `question_queries`는 같은 질문의 검색어,
  `collected_originals`는 성공한 개별 다운로드다. SQLite 연결·커서는 매번 명시 종료한다.
- `services/rag_service.py`: 수집 계획→다운로드→검증된 색인 후 원장 완료. 재질문에 검색·선별·다운로드를 반복하지 않는다.
- `vectorstore/documents.py`: 청킹/색인. `doc:{item_receipt}:{document_receipt}:{content_and_config_hash}:{index}`.
  본문/설정 변경 시 새 청크를 검증한 뒤 **해당 항목/원문**의 이전 청크만 제거한다. 메타 컬렉션이나 다른 항목은 삭제하지 않는다.
- `rag/retrieval.py`: DB의 선택 메타데이터를 필수 포함, 문서는 item_rcept_no로 필터, ID/동일 본문 중복 제거.
- `rag/pipeline.py`: LangGraph `START → retrieve → generate → END`. 프롬프트는 1 검색어/2 후보선별/3 답변으로 분리.
- `rag/llm.py`: GMS만 사용, JSON/허용 후보/인용 번호 검증, 인증 오류 즉시 중단, 일시적 HTTP 오류 최대 3회, timeout·간격 유지.
  기존 F2003 추출은 기존 재시도 정책(파싱 최대 2회 재시도, HTTP 실패 즉시 중단)을 유지한다.
- `services/discovery.py`: 조건 선별. 메타데이터에 없는 본문 조건은 확인할 수 없으므로 제외하도록 지시한다.
- `services/runtime.py`, `ask.py`, `app.py`: 실제 구성·CLI·UI. 모델은 실제 검색/색인 시에만 지연 로딩한다.
- `ui/chat.py`: 공시별 세션 기록. 영구 사용자 DB/회원 기능 없음.

기본 1000/200 청킹은 한국어 문맥을 유지하면서 표/문단 경계에 우선 분할하려는 시작값이다.
Top-k는 전체 근거 수이며 기본 5=고정 메타1+본문 최대4. 동일 본문 중복 제거 때문에 실제 근거 수는 더 적을 수 있다.
이 값들의 실제 품질 최적화는 미검증이며 임시 DB 테스트에서 설정 변화에 따른 청크/근거 수 차이는 확인한다.
프로필/1024차원 불일치는 오류로 중단하며 기존 OpenAI/다른 모델 DB에 덮어쓰지 않는다.

## 실제 문서 묶음 형식

`export_documents`가 실제 다운로드로 생성하는 UTF-8 JSON을 사용한다.
최상위는 `{"schema_version":1,"documents":[...]}`이며 각 항목은 다음 필드다.

| 필드 | 의미 |
|---|---|
| item_rcept_no | 내보낼 때의 선택 공시(읽을 때 선택 항목으로 재연결) |
| document_rcept_no | 원문 14자리 접수번호 |
| title, corp_code | 원문 제목, 공식 8자리 기업코드 |
| source_url | 인증키 없는 공식 DART 뷰어 URL, rcpNo=원문 접수번호 |
| source_type | opendart_document |
| text | 실제 원문 텍스트, 빈 본문 금지 |
| collected_at | 시간대 포함 ISO 수집 시각 |

선택 원문이 묶음에 없으면 실패하며 다른 문서나 메타데이터로 본문을 만들어 대체하지 않는다.
오프라인 묶음 자체의 출처·이용 권한·실제성은 제공자가 확인해야 하며 형식 검증만으로 진위를 보증하지 않는다.

## 제출용 실행 체크리스트

아래는 **아직 실제 완료로 체크하지 않은** 필수 항목이다. Mock 통과 기록과 분리해서 실제 실행 후 증거를 채운다.

- [ ] 실제 메타데이터 총수=색인 수, 같은 입력 2회 실행 수 불변, 텍스트 1건 캡처
- [ ] 실제 질문의 추출 검색어·선별/제외 문서·선택 원문 필수 포함 캡처
- [ ] 같은 질문 재실행 시 외부 수집 미발생, 청크 크기/중복 변경 시 수 변화
- [ ] Top-k 변경 결과, LangGraph 구조, 두 출처 유형·실제 인용 번호 일치
- [ ] 문서 밖 질문의 미확인 답변, 무인용 안내
- [ ] 공시별 채팅 복귀, 실제 조건 일치/불일치, 위험 분석과 근거
- [ ] 수집·생성 진행 상태, 키 누락·색인 없음, 금융 면책 화면
- [ ] 실제 응답 시간 측정(NF2001), 원장 재수집 방지(NF2002)
- [ ] 제출물 비밀키/로그 검사(NF2003/4), 책임 분리(NF2005)
- [ ] 외부 API 이용 정책·간격·재시도 확인(NF2006), 출처·이용 조건 확인(NF2007)
- [ ] 사용자 실제 브라우저 스크린샷, 제공 셀프 체크리스트, 옆 교육생 상호 점검
- [ ] 요구사항/설계/검증/README/소스 제출 ZIP 구성(PDF p.21~23)

스크린샷·상호 검증·실제 응답 품질을 가상 결과로 채우지 않는다.
이번 구현은 기능 경로와 오프라인 테스트 증거를 제공하며, 이 목록의 실제 수행 완료를 주장하지 않는다.
