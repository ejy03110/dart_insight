## 변경한 동작

- 홈·API/저장 통합 탐색·분석 기록에서 공시를 열면 같은 분석 경로로 진입한다.
  상세의 준비/진행 상태가 먼저 표시되며 본문 불러오기·색인·분석 버튼을 누를 필요가 없다.
- 선택 공시의 메타데이터가 없으면 공식 목록에서 받은 해당 1건만 `dart_metadata`에 추가한다.
  기존 항목은 수정하지 않는다. F2001 일괄 입력의 100건 이상 검증을 완화하거나 가상 항목을 추가하지 않는다.
- `Runtime`은 필요한 기존 컬렉션을 열고, 없는 컬렉션만 같은 기존 경로에 준비한다. 다른 모델/프로필 DB를 덮어쓰지 않는다.
- 본문은 기존 원장의 완전한 원문으로 예상 전체 청크와 실제 ID/본문/메타데이터를 대조한다.
  “청크 1개 존재”만으로 완료로 간주하지 않는다. 완료되었으면 원문 재수집·문서 재색인·검색어 재추출 없이
  해당 원문 범위의 의미 검색과 LangGraph 답변 생성으로 진행한다.
- 미색인은 기존 검색어 추출→외부 검색→독립 후보 선별→원문 전체 파싱→청킹/색인→LangGraph를 재사용한다.
  자동 핵심 분석에서는 **선택 원문 1건**으로 후보 입력을 제한한 뒤 선별 프롬프트를 실행한다.
  따라서 LLM이 선별한 외부 문서를 나중에 몰래 버리지 않는다. 전체 검색 후보는 원장에 그대로 보존해 후속 질문이 재선별할 수 있게 하고, 예산상 제외와 LLM 제외를 따로 기록한다. 명시적 후속 질문의 폭넓은 후보 검색은 유지한다.
- 파싱 실패·다중 XML 중 일부 손상·빈 원문은 답변 생성으로 넘어가지 않는다. 정상 원문이 원장에 있고
  같은 청킹 설정에서 일부 청크만 빠진 경우에는 누락분을 복구하며 원문을 다시 받지 않는다.
- 레거시 본문에 검증 가능한 원문 기록이 없거나 모델/청킹 내용이 다르면 자동 초기화·전체 재색인으로 우회하지 않는다.
  기존 자료를 보존하고 오류와 재시도를 표시한다. 이런 데이터까지 성공한다고 보장하지 않는다.
- 성공/실행/실패 상태와 결과는 접수번호별 세션에 보존한다. rerun·위젯·목록 왕복·기록 복귀에서 중복 분석하지 않는다.
  실패 시에만 명시적으로 재시도한다. 인증/원문/색인/호출 한도/응답 검증 오류를 정제한 이유로 안내한다.
- 분석이 완료된 뒤 후속 질문 입력창이 활성화된다. 공급자에게 전달하는 대화 문맥에는 해당 공시의 자동 분석과
  후속 대화를 함께 넣되, 화면 채팅 기록에 자동 분석을 중복 삽입하거나 다른 공시의 기록을 섞지 않는다.
- 공시 원문 전체·표 열람은 별도 접기 영역으로 남긴다. 이 영역의 선택적 열람 버튼은 RAG 실행의 전제 조건이 아니다.

- 기업별 최대 3건을 압축형 카드에 표시한다. 데스크톱 3열, 태블릿 2열, 모바일 1열이며 제목 버튼으로 상세를 연다.
- 홈 브리핑은 최근 7일 중 최신 접수일/접수번호의 대표 **1건/세션**을 고정한다. 본문이 없더라도 자동 준비한다.
  카드를 보거나 화면을 갱신할 때 대상을 바꾸지 않는다. 실패하면 결과를 꾸미지 않고 실패/재시도/다른 공시 직접 선택을 안내한다.
  자동으로 다음 후보를 연쇄 수집·분석하지 않는다. 원문 1건, 검색어·재시도는 기존 상한을 유지한다.
- 브리핑에 기업·제목·공시 접수일과 실제 인용 근거를 표시한다. 인증/최근 공시 없음은 “실행하지 않음”으로 안내한다.
- 고정 Streamlit 헤더 높이보다 큰 상단 여백(데스크톱 5rem/모바일 4.5rem)을 둔다.
  상세 진입·공시 변경·새로고침 때만 공식 `st.html(..., unsafe_allow_javascript=True)`의 고정 스크립트로
  메인 스크롤을 상단으로 돌린다. 사용자 데이터는 스크립트에 넣지 않으며 채팅/읽기 중 rerun에는 스크롤을 강제로 바꾸지 않는다.
  표시 요소 위치와 원문 expander key도 고정해 rerun 시 원문 영역이 갑자기 닫히지 않도록 했다.

- API 오류를 결과 없음으로 바꾸지 않는다. API 실패 중에도 조건에 맞는 저장 공시를 열 수 있다.
- 자연어 검색은 기존 메타데이터 의미 검색 + 독립 LLM 선별을 유지한다. 성공 시 조건에 맞는 결과만 제시하며,
  조건이 검증되지 않은 API 결과는 섞어 표시하지 않는다. 조건 해제로 통합 목록으로 돌아간다.
- 사업/반기/분기/감사 및 일부 보고서 유형과 명시적 `제외/빼고/말고` 조건, 기업 제외, 정정 제외를 최종 결과에도 적용한다.
  중점 표기 `·/ㆍ`와 공백 차이를 정규화한다. 일반 자연어 논리 전체를 보장하는 파서는 아니다.
- 전체 기업 90일/3개월 제한, 제목 조회 1,000건 상한, API 오류 캐시, 하단 페이지 버튼,
  상세→목록 조건/페이지 복귀와 직접 URL 접근을 유지한다.

**통합 범위의 한계:** 전체 API를 내려받아 단일 전역 정렬·합계·페이지를 만드는 방식이 아니다.
API의 현재 서버 페이지와 저장 결과를 한 화면에서 함께 탐색한다. 페이지가 바뀌면 이전 API 페이지의 항목이
저장 결과에 다시 보일 수 있지만, 같은 화면에서 중복 카드를 표시하지 않는다. 자연어 조건은 저장 색인에만 적용한다.
기존 Streamlit 브라우저 history의 모든 과거 쿼리 복원 제약은 `disclosure-search.md`대로 남는다.

### P0: 홈 최근 공시·자동 브리핑

`ui/recent.py`, `ui/dashboard.py`, 기존 `services/recent_disclosures.py`:

- 한 기업 카드씩 가로 전환한다. 이전/다음·현재 위치·기업명·제목·제출일·유형·분석 가능 이유를 표시한다.

  세션에 대상을 고정하고 결과/실패 상태를 보존한다. 카드 이동으로 추가 대표를 분석하지 않는다.
  분석 가능한 최근 공시가 없으면 이유를 표시하며 대체·가상 분석을 만들지 않는다.

### P0: 상세 자동 분석과 필수 기능 보존

`ui/analysis.py`, `services/runtime.py:analysis_readiness`, `app.py`:

- 본문 준비가 확인된 공시 상세/분석 화면 진입 시 자동 분석한다. 정상 흐름의 실행 버튼을 없앴다.
- 원문 준비 판별은 기존 DB의 모델/프로필/1024차원, `item_rcept_no`, **선택 원문 자체의** `document_rcept_no`,

- 분석 결과와 실행 상태는 접수번호별로 저장한다. rerun·위젯·복귀·브리핑↔상세 전환에서 같은 분석을 재호출하지 않는다.

- **F2003~F2005 보존:** 본문 미색인 공시의 *자동* 분석만 막는다. 메타데이터가 있는 공시에 사용자가 직접 질문하면
  기존 원문 수집→청킹/색인→검색→생성 경로를 사용할 수 있다. 목록만의 신규 공시는 임의로 색인하지 않는다.
- 공시별 대화 격리, 최근 대화 문맥, 분석과 채팅 분리, 기록 복귀를 유지한다.
- 대화/분석은 세션 기반이다. F5/새 세션에서 기록을 영구 복원하는 기능은 추가하지 않았다.
  새 세션에서 분석 가능한 상세를 열면 다시 1회 분석될 수 있다. 홈도 새 세션마다 대표 1회이며 전역 LLM 캐시는 아니다.
- 최초 질문의 기존 RAG 준비 과정은 필요한 관련 문서를 추가 수집/색인할 수 있다. 전체 DB를 일괄 재색인하지 않는다.

## 파싱·청킹 진단

확인한 코드 경로:

1. `services/original_documents.py:_xml_text`는 XML `itertext()` 또는 HTML 표시 텍스트를 줄바꿈으로 합친다.
2. 이 단계에서 표의 셀 텍스트는 남지만 `tr/td`, 행·열·병합 관계는 사라진다.
3. `vectorstore/documents.py:document_chunks`는 이미 평탄화된 텍스트를 문자 길이/구분자로 나눈다.
   따라서 표 헤더와 수치가 다른 청크로 나뉠 수 있다. 검색은 같은 ID/완전히 같은 텍스트를 제거하지만 겹침이 있는 유사 청크까지 합치지는 않으며 표 구조를 복원하지 않는다. 근거 번호별 구간은 구분해 표시한다.
4. 기존 근거 UI는 해당 청크 텍스트와 내부 ID를 그대로 표시했다. ID 노출은 이번에 고쳤지만, 잃어버린 표를 UI에서 추정 복원하지 않았다.
5. 별도 원문 열람 `services/document_view.py:_structured`는 검증된 원문의 행·열·병합을 보존하는 경로가 있다.
   이번 차트는 이 경로의 표만 사용하며, 본문 구조를 재현하지 못하면 전체 텍스트·공식 링크로 안내한다.

요청 사례 **20251231000603 원본 ZIP·캐시·Chroma 청크는 이 환경에 없고 DART 키도 없다.**
따라서 해당 원본과 청크의 독립 대조, 홍창표·270주·0.00%·발행주식 총수·장내매수 여부는 이번에 검증하지 못했다.
사용자 제공 수치를 프로그램에 실제 데이터로 삽입하지 않았다. 차트 브라우저 검증의 0→270은 명시적인 **합성 테스트 표**다.

전체 재색인과 자동 파서 전환은 하지 않았다. 후속 조치는 실제 ZIP을 확보해 원문 표와 기존 청크를 비교한 후,
구조화 텍스트/원문 구조를 별도 버전으로 보존하고 **새 DB 경로**에서 해당 자료만 실험하는 것이다.
기존 DB를 백업·보존하고 검색/인용/수치 일치 및 청킹 프로필을 비교하기 전 운영 파서를 바꾸지 않는다.
