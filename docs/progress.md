## 새 대화에서 이어갈 순서

1. 루트 `AGENTS.md`와 이 문서를 읽고 Git 브랜치·작업 변경·실제 로컬 파일 존재를 확인한다.
2. 사용자가 지정한 다음 작업 범위를 따른다. F2002 실제 검증을 진행하려면 먼저 실제 JSON의 dry-run 결과를 확보한다.
3. 실제 BGE-M3 색인은 사용자 로컬에서 새 DB 경로에 실행한다(첫 다운로드·CPU/RAM 자원 필요).
   같은 입력/DB/모델로 두 번 실행한 전체·기업별 수와 `count_delta=0`, `embedded_count=0`을 기록한다.
4. 이후 요청된 단계에서 F2003~F2005를 구현하고 선택 공시 자체 원문·후보 선별·별도 컬렉션 조건을 지킨다.
   이어 F2006~F2008, F2009~F2012를 순서대로 검증한다.
5. 기능 변경마다 결과·증거 출처·미검증 사항을 이 문서에 갱신하고 원본 4장·6장 증빙을 별도 준비한다.

실행 방법은 [f2001.md](f2001.md), [f2002.md](f2002.md), [README](../README.md)를 재사용한다.
안전한 다음 검증 명령의 예시는 아래와 같다. 경로는 실제 보유 파일로 바꾼다.

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m dart_insight.index_metadata \
  --input .local/data/metadata/run-7kvbb30c/collection.json --dry-run
```

Git 이력 기준: 초기 구조 `f0704a9`, F2001 `7b1f335`, F2002 `dce34d8`.
F2002까지 `feat/dart-insight-initial` 원격 push를 확인했다. `master` 직접 push/병합은 하지 않았다.
이후 로컬 BGE-M3 전환 작업의 commit/push 상태는 Git 이력·원격에서 확인한다.
사용자는 작업 완료 때마다 작업 브랜치에 commit/push하도록 상시 요청했다. master 직접 push/병합 금지는 유지한다.
현재 브랜치·원격 상태는 변경될 수 있으므로 새 작업에서 재확인한다. 이 문서 자체의 commit/push 상태는 Git 이력과 원격을 확인한다.
